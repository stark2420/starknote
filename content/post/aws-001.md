## 事前準備
### AWSアカウント作成
### IAMで作業用ユーザ作成
AWSアカウントを作成するとルートユーザーが作成される．普段は作業用ユーザ（IAMユーザ）を利用するのが基本．
- ルートユーザ
  - アカウントの変更・解約，プラン変更などの時のみ使用
- 作業用ユーザ（IAMユーザ）
  - AWSで作成するユーザ
  - 作業者ごとに個別に作成
  - 通常の作業はIAMユーザで実施

`サービス > IAM > ユーザー > ユーザーを追加` から作成．

![This is a image](https://raw.githubusercontent.com/stark2420/starknote/refs/heads/main/static/image/aws-001/im01.png) 

チームメンバーのユーザ作成する場合は，「自動生成パスワード」＋「パスワードのリセットが必要」にするとよい．

作成すると，AWS マネジメントコンソールへのリンク「 https://2xxxxxxxx5.signin.aws.amazon.com/console 」が作成される．

### ルーティングを設定
①インターネットゲートウェイを作成し、VPCにアタッチする．

`AWSマネジメントコンソール＞サービス＞VPC＞インターネットゲートウェイ＞インターネットゲートウェイの作成`
- 名前タグ：aws-igw

`インターネットゲートウェイ＞作成したaws-igwを選択＞アクション＞VPCにアタッチ`
- VPC*：aws-vpc を選択

`ルートテーブル＞作成したaws-public-routeを選択＞アクション＞サブネットの関連付けの編集`

## Webサーバの構築
### EC2インスタンスの作成
`AWSマネジメントコンソール＞サービス＞EC2＞インスタンス＞インスタンスの作成`
- 手順1：Amazon マシンイメージ(AMI)
  - Amazon Linux 2 AMI (HVM), SSD Volume Type（無料利用枠の対象）
- 手順2：インスタンスタイプの選択
  - t2.micro（無料利用枠の対象）
- 手順3：インスタンスの詳細の設定
  - ネットワーク：aws-vpc を選択
  - サブネット：aws-public-subnet を選択
  - 自動割り当てパブリックIP：有効
  - キャパシティーの予約：なし
- 手順4：ストレージの追加
- 手順5：タグの追加
  - キー：Name
  - 値：aws-web
- 手順6：セキュリティグループの設定
  - 新規作成
  - セキュリティグループ名：aws-web-sg

既存のキーペアを選択するか、新しいキーペアを作成します （EC2へSSHするための鍵）

![This is a image](https://raw.githubusercontent.com/stark2420/starknote/refs/heads/main/static/image/aws-001/im07.png) 

### セキュリティグループの設定
現時点では，sshでしかEC2へアクセスできないので，httpを許可する．

`AWSマネジメントコンソール＞サービス＞EC2＞セキュリティグループ＞インバウンド＞編集` で HTTP のポート80を許可．

![This is a image](https://raw.githubusercontent.com/stark2420/starknote/refs/heads/main/static/image/aws-001/im08.png) 

### EC2へSSH接続し，Apacheのインストール

`AWSマネジメントコンソール＞サービス＞EC2＞インスタンス` からパブリックIPを確認．

```
$ chmod 600 ~/Desktop/aws-keypair.pem
$ ssh -i ~/Desktop/start-aws-keypair.pem ec2-user@54.218.66.178

[ec2-user@ip-10-0-10-178 ~]$

[ec2-user@ip-10-0-10-178 ~]$ sudo systemctl enable httpd.service
[ec2-user@ip-10-0-10-178 ~]$ exit

```

## DBサーバの構築
### プライベートサブネットの作成
`AWSマネジメントコンソール＞サービス＞VPC＞サブネット＞サブネットの作成`
- 名前タグ：aws-private-subnet
- VPC*：aws-vpc を選択
- アベイラビリティーゾーン：どれでもよい
- IPv4 CIDR ブロック*：10.0.20.0/24

もうひとつ，アベイラビリティーゾーンの異なるサブネットを作成しておく．
(RDSには，複数の異なるアベイラビリティーゾーンに置くことで可用性を高める機能があり，複数用意しないと使用できないため．)

`AWSマネジメントコンソール＞サービス＞VPC＞サブネット＞サブネットの作成`
- 名前タグ：aws-private-subnet
- VPC*：aws-vpc を選択
- アベイラビリティーゾーン：どれでもよい
- IPv4 CIDR ブロック*：10.0.21.0/24

### セキュリティグループの作成
WebサーバからDBサーバへアクセスできるように，セキュリティグループを作成する

`AWSマネジメントコンソール＞サービス＞EC2＞セキュリティグループ＞セキュリティグループの作成` 
- セキュリティグループ名：aws-db-sg
- インバウンド
  - タイプ：MYSQL/Aurora
  - ポート範囲：3306
  - ソース：aws-web-sg

`AWSマネジメントコンソール＞サービス＞RDS＞データベース＞データベースの作成` 
- MySQL
- テンプレート：無料利用枠
- DBインスタンス識別子：aws-mysql
- マスターユーザー名：root
- 既存の VPC セキュリティグループ：aws-db-sg
- 追加設定
  - 最初のデータベース名：aws_dev

### WordPressのインストール

```
[ec2-user@ip-10-0-10-178 ~]$ sudo amazon-linux-extras install -y php7.2
[ec2-user@ip-10-0-10-178 ~]$ sudo yum install -y php php-mbstring

[ec2-user@ip-10-0-10-178 ~]$ cd ~
[ec2-user@ip-10-0-10-178 ~]$ wget https://ja.wordpress.org/latest-ja.tar.gz
[ec2-user@ip-10-0-10-178 ~]$ tar xzvf latest-ja.tar.gz

[ec2-user@ip-10-0-10-178 ~]$ cd wordpress/
[ec2-user@ip-10-0-10-178 wordpress]$ sudo cp -r * /var/www/html/
[ec2-user@ip-10-0-10-178 wordpress]$ sudo chown apache:apache /var/www/html/ -R
[ec2-user@ip-10-0-10-178 ~]$ sudo systemctl status httpd.service
[ec2-user@ip-10-0-10-178 ~]$ sudo systemctl restart httpd.service
[ec2-user@ip-10-0-10-178 ~]$ sudo systemctl status httpd.service
[ec2-user@ip-10-0-10-178 ~]$ exit
```
